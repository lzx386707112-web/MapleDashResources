## 经验教训

- GitHub 单文件 >100MB 硬限制：`Data/UI/Enchant.img`(105MB) 用 Git LFS 处理，`.gitattributes` 跟踪该路径
- `git push origin main` 会把所有未推送提交打进**一个包**；分块提交必须配合逐 SHA 推送（`git push origin <sha>:main`）才有效
- HTTP 408/hangup：大包整体缓冲发送会被 GitHub 掐断；`http.postBuffer` 调低（50MB）强制 chunked 流式
- 环境变量代理（WorkBuddy 内部 50284）会覆盖 git config 的 http.proxy（用户自己的 7890）；大包时两者都曾卡住，网络时段差异大（5MB/s ↔ 40KB/s）
- 后台脚本里中文提交消息曾乱码（locale 问题），脚本需 `export LANG=en_US.UTF-8`
- 用户游戏资源目录正被外部进程持续写入，git status 的 `??` 会折叠未跟踪目录，实际文件数要用 `git ls-files --others` 统计
